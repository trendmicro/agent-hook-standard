# Governance

The Agent Hook Spec is developed in public. Contributors, implementers, and
maintainers use GitHub Discussions to develop ideas before proposing a formal
change.

## RFC lifecycle

1. Open an RFC Proposal discussion in GitHub Discussions. Describe the problem,
   the intended outcome, and known alternatives.
2. After discussion, open a pull request containing a numbered RFC based on
   [`rfcs/0000-template.md`](rfcs/0000-template.md). The RFC must link to its
   Discussion.
3. Keep the RFC open for public review for at least 14 calendar days.
4. When review is complete, active maintainers cast and record their votes in
   the RFC's front matter and decision record.
5. An Accepted RFC is implemented through follow-up pull requests that update
   the canonical specification, schemas, fixtures, examples, and website as
   applicable.

## Voting and consensus

An RFC needs a quorum of two active maintainer votes. It is accepted when yes
votes outnumber no votes. Abstentions count toward quorum but not the majority.
Maintainers must resolve substantive objections or record why an objection did
not block the decision before voting closes.

The RFC status is one of `Discussion`, `Draft`, `Accepted`, `Rejected`,
`Withdrawn`, or `Superseded`. The final RFC records the review dates, each
maintainer vote, the decision, and any RFC it supersedes or is superseded by.
